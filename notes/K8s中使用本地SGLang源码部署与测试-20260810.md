## 7. 首次启动失败及处理

第一次使用本地源码启动时，服务在依赖版本检查阶段退出：

```text
Exception: sglang-kernel is installed with version 0.4.3,
which is less than the minimum required version 0.4.5.
```

本地源码的 `python/pyproject.toml` 要求：

```text
sglang-kernel==0.4.5
```

Pod 当前镜像安装的是 `sglang-kernel==0.4.3`。为避免在运行 Pod 中联网升级二进制依赖，本次测试使用源码内置的版本检查开关：

```bash
export SGLANG_SKIP_SGL_KERNEL_VERSION_CHECK=1
```

该设置只跳过版本检查，不会升级 Kernel。正式构建镜像时应安装与本地源码匹配的 `sglang-kernel==0.4.5`，避免潜在 ABI 或功能不兼容。

## 8. 使用本地源码启动服务

启动前设置：

```bash
export PYTHONPATH=/tmp/sglang-local-20260810-192359/python:${PYTHONPATH}
export SGLANG_SKIP_SGL_KERNEL_VERSION_CHECK=1
```

后台启动器实际执行的服务命令为：

```bash
set -o pipefail
sglang serve \
  --trust-remote-code \
  --model-path /userdata/DeepSeek-V4-Flash \
  --served-model-name deepseek-v4-flash \
  --tp 8 \
  --mem-fraction-static 0.90 \
  --enable-nsa-prefill-context-parallel \
  --nsa-prefill-cp-mode round-robin-split \
  --moe-runner-backend marlin \
  --tool-call-parser deepseekv4 \
  --reasoning-parser deepseek-v4 \
  --host 0.0.0.0 \
  --port 8080 \
  --enable-metrics \
  --enable-cache-report \
  2>&1 | tee -a /tmp/dsv4-flash-local-source-20260810-192359.log
```

启动器通过 `subprocess.Popen(..., start_new_session=True)` 在独立会话中运行，使 `kubectl exec` 退出后服务继续运行。

## 9. 启动过程观察

第二次启动约在 `19:28` 进入 Scheduler 初始化，`19:40:49` 完成 Uvicorn 启动，`19:41:11` 完成内部生成自检并进入完全就绪状态。

首次从新源码路径启动需要重新执行 CUDA JIT、DeepGEMM 预编译和 CUDA Graph 捕获，因此耗时约 12 分钟。日志显示 CUDA Graph 捕获耗时约 398.6 秒。

启动期间观察到以下非致命提示：

- `--enable-nsa-prefill-context-parallel` 已弃用，建议改用 `--enable-prefill-cp`。
- `--nsa-prefill-cp-mode` 已弃用，建议改用 `--cp-strategy`。
- 可选模型 `inkling` 缺少 `helion`，被 SGLang 忽略。
- DeepSeek V4 tokenizer 最终仍为通用 `TokenizersBackend`，可能缺少模型特定属性。

在 Uvicorn 刚启动但内部 `/generate` 自检尚未完成时，`/health` 曾短暂返回 `503`；内部自检完成后恢复为 `200`。

```bash

  -c sglang-leader -- /bin/kill -- -12300
```

## 13. 注意事项

- `/tmp/sglang-local-20260810-192359` 属于 Pod 内临时部署目录；Pod 被删除或重新创建后可能丢失。
- 当前运行服务依赖该目录，服务运行期间不要删除它。
- 当前测试跳过了 `sglang-kernel` 版本检查；正式镜像应升级到 `0.4.5`。
- 本次仅同步了运行服务所需的 `python/sglang` 源码树，没有同步 `.git`、文档、测试数据和构建目录。
