# HiCache DSV4 PP 索引错位修复说明

## 修改文件

`sglang/python/sglang/srt/mem_cache/hybrid_cache/hybrid_pool_assembler.py`

## 修改内容

### 修改1：c4_state_global_layers 索引偏移（第302行）

**修改前：**
```python
c4_state_global_layers.append(layer_id)
```

**修改后：**
```python
c4_state_global_layers.append(layer_id + kvcache.start_layer)
```

### 修改2：c128_state_global_layers 索引偏移（第305行）

**修改前：**
```python
c128_state_global_layers.append(layer_id)
```

**修改后：**
```python
c128_state_global_layers.append(layer_id + kvcache.start_layer)
```

## 修改原因

在 PP=4 配置下，DSV4 的 61 层被分成 4 段，每个 PP stage 处理约 15 层。原代码中 `enumerate()` 产生的 `layer_id` 是从 0 开始的局部偏移量，而 `compress_state_pools` 数组使用全局绝对索引赋值，导致 PP1~3 节点用局部索引访问全局数组时命中了 `None` 位置，报错 `state_pools must not contain None`。

加上 `kvcache.start_layer` 偏移后，`c4_state_global_layers` 和 `c128_state_global_layers` 中存储的索引变为全局绝对层号，与 `compress_state_pools` 的赋值索引一致。

## 影响范围

仅影响 `c4_state_global_layers` 和 `c128_state_global_layers` 两个列表中存储的索引值。下游使用：

1. `compress_state_pools[layer_id]` / `indexer_compress_state_pools[layer_id]` — 直接受益，修复了索引错位
2. `c4_state_mapping` / `c128_state_mapping` — 作为 `build_pool_entry` 的 `layer_mapping` 参数，key 是局部 `layer_id`，value 是 `local_id`，不受此修改影响
3. `c4_kv_pool` / `c4_indexer_kv_pool` 等 PagedHostPool — 使用 `device_buffers` 和 `layer_mapping`，不直接使用这两个列表

## 验证

修复后4节点 HiCache 服务正常启动，3轮压测均通过，Input throughput 从 4456 提升至 7617 tok/s。
