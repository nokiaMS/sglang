# dsv4-pro-sglang-agg-tp4dp2pp4-mem095-maxreq64-swa02-cps4096-nohicache 测试结果分析

## 结论

去掉 HiCache 后，`TP=4 DP=2 PP=4 + --enable-dp-attention` 仍然失败，且失败点与有 HiCache 场景一致：`_DpGatheredBufferWrapper._dp_max_padding` 未初始化导致 scheduler 子进程抛出 `AttributeError`。

这说明本轮失败不是 HiCache 引起的。根因仍然落在 SGLang 的 `PP + multi-node DP attention` 路径。

## 实际配置

| 参数 | 值 |
| --- | --- |
| tp-size | 4 |
| dp-size | 2 |
| pp-size | 4 |
| enable-dp-attention | true |
| enable-hierarchical-cache | false |
| nnodes | 4 |
| mem-fraction-static | 0.95 |
| 启动参数 chunked-prefill-size | 4096 |
| 实际 chunked-prefill-size | 2048 |

日志中 `server_args` 明确显示：

```text
enable_hierarchical_cache=False
```

同时 DP attention 仍然自动把 `chunked_prefill_size` 从 4096 调整为 2048：

```text
DP attention is enabled. The chunked prefill size is adjusted to 2048
```

## 失败现象

服务没有进入可压测状态。pod0 曾短暂启动 HTTP 服务：

```text
Uvicorn running on http://0.0.0.0:8080
```

随后 scheduler 子进程崩溃，服务整体退出，因此未执行 C10/C30/C60 bench。

## 关键错误

node1 日志中最关键的异常：

```text
AttributeError: type object '_DpGatheredBufferWrapper' has no attribute '_dp_max_padding'
```

对应调用链：

```text
scheduler_pp_mixin.py:event_loop_pp()
  -> _pp_recv_proxy_tensors()
  -> _pp_recv_typed_dict()
  -> pp_group.recv_tensor_dict(...)
  -> all_gather_group.all_gather(...)
  -> dp_attention.py:is_allocation_symmetric()
  -> is_dp_max_padding()
  -> _DpGatheredBufferWrapper.is_dp_max_padding()
```

其他节点上的：

```text
RuntimeError: ... gloo/transport/tcp/pair.cc:547 Connection closed by peer
```

是 scheduler 退出后的级联 PP 通信断连，不是最初根因。

## 和有 HiCache 场景对比

| 场景 | HiCache | 结果 | 根因 |
| --- | --- | --- | --- |
| tp4dp2pp4 + HiCache | 开启 | C10 warmup 失败 | `_dp_max_padding` 未初始化 |
| tp4dp2pp4 nohicache | 关闭 | 启动/预热阶段失败 | `_dp_max_padding` 未初始化 |

两次测试的根因一致，因此可以排除 HiCache 作为直接触发因素。更准确的描述是：当前 SGLang 版本在 `PP + multi-node DP attention` 组合下存在 DP attention buffer 状态初始化顺序问题。

## 建议

1. 先修复 SGLang DP attention 中 `_DpGatheredBufferWrapper._dp_max_padding` 的初始化问题。
2. 修复后先用 no-HiCache 场景做最小请求验证，再回到 HiCache 场景。
3. 最小验证建议：`random-input-len=1000`、`num-prompts=1`、`max-concurrency=1`。
