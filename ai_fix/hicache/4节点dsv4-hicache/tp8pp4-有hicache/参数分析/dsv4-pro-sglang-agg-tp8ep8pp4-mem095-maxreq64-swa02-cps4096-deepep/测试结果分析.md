# DeepEP (EP=8) 测试结果分析 — 不可用

## 测试配置

| 配置项 | 基线 (cps4096) | 本测试 (deepep) |
|---|---|---|
| ep-size | 默认 (1) | **8** |
| moe-a2a-backend | none | **deepep** |
| moe-runner-backend | marlin | 需更换 |
| 其余参数 | 相同 | 相同 |

## 尝试过程

### 尝试1: marlin + deepep

```
NotImplementedError: Runner backend MoeRunnerBackend.MARLIN requires a fused func
for a2a backend deepep, but none is registered.
```

**原因**: Marlin 是 fused-only runner（没有独立 runner_core），只有 `("none", "marlin")` 的 fused func 注册，没有 `("deepep", "marlin")` 组合。

### 尝试2: triton + deepep

```
AssertionError: Pre-permute function for deepep_normal to triton is not registered
```

**原因**: Triton runner 虽然有独立 runner_core，但 DeepEP 需要专门的 pre-permute 函数将 DeepEP dispatcher 输出转换为 runner 输入格式。当前只注册了 `("standard", "triton")` 和 `("standard", "deep_gemm")`，没有 `("deepep_normal", "triton")`。

### 尝试3: deep_gemm + deepep

```
tvm.error.InternalError: Assertion error:
ab.scalar_type() == kPackedFP4 and arch_major == 10
```

**原因**: DeepGEMM runner 要求：
1. **FP4 量化权重** (`kPackedFP4`) — 当前模型使用 fp8_e4m3 量化
2. **GPU 架构 arch_major == 10** (Blackwell/B200) — H800 是 arch_major=9 (Hopper)

## DeepEP 兼容性总结

| Runner | DeepEP 兼容 | 失败原因 |
|---|---|---|
| marlin | 否 | 无 `(deepep, marlin)` fused func 注册 |
| triton | 否 | 无 `("deepep_normal", "triton")` pre-permute 注册 |
| deep_gemm | 否 | 需要 FP4 量化 + Blackwell GPU |
| aiter | 否 | 无 `("deepep", "aiter")` fused func |
| flashinfer_trtllm | 否 | 无 `("deepep", "flashinfer_trtllm")` 注册 |

## 当前环境不满足的条件详细分析

### 条件1：moe-runner-backend 与 DeepEP 的兼容性

DeepEP 需要一个与之兼容的 MoE runner。当前 sglang 代码中各 runner 与 DeepEP 的兼容情况：

| Runner | 是否注册了 DeepEP 的 fused/pre-permute | 当前能否使用 |
|---|---|---|
| **marlin** | 无 `("deepep", "marlin")` fused func | **不兼容** |
| **triton** | 无 `("deepep_normal", "triton")` pre-permute | **不兼容** |
| **deep_gemm** | 有 `("deepep_normal", "deep_gemm")` pre-permute | 兼容（但见条件2/3） |
| **aiter** | 无 `("deepep", "aiter")` fused func | **不兼容** |
| **flashinfer_trtllm** | 无 DeepEP 注册 | **不兼容** |

唯一兼容的 `deep_gemm` runner 还有额外硬件/模型要求（见下），其余 runner 在 sglang 代码中均未注册 DeepEP 所需的转换函数。

### 条件2：deep_gemm runner 要求 FP4 量化权重

```
tvm.error.InternalError: ab.scalar_type() == kPackedFP4
```

**当前环境**：
- DSV4 是 **FP8 模型**（fp8 weight + fp8_e4m3 KV cache），通过 marlin 格式加载

**deep_gemm 要求**：
- 模型权重：**FP4 量化 (kPackedFP4)** — 一种更激进的 4-bit 量化格式

| | FP8 (DSV4 当前) | FP4 (deep_gemm DeepEP 要求) |
|---|---|---|
| 精度 | 8-bit 浮点 | 4-bit 浮点 (packed) |
| 权重体积 | 较大 | 较小（压缩比约2x） |
| sglang dtype | fp8_e4m3 | kPackedFP4 |

DSV4 是 FP8 模型，而 deep_gemm 的 DeepEP 内核期望接收 FP4 packed 格式的权重张量，格式不匹配。

### 条件3：deep_gemm runner 要求 Blackwell GPU

```
tvm.error.InternalError: arch_major == 10
```

**当前环境**：
- GPU：**4节点 × 8×H800 80GB** — Hopper 架构，`arch_major = 9`

**deep_gemm 要求**：
- GPU 架构：**Blackwell**（B200/B100），`arch_major = 10`

Hopper 与 Blackwell 是 NVIDIA 不同的 GPU 架构代际：

| | Hopper | Blackwell |
|---|---|---|
| **代表产品** | H100, **H800** | B200, B100 |
| **arch_major** | 9 | 10 |
| **HBM** | HBM3 | HBM3e |
| **量产时间** | 2022年 | 2024年底 |
| **定位** | 当前一代数据中心GPU | 下一代数据中心GPU |

H800 是 Hopper 架构，Blackwell 是 Hopper 的下一代架构，它们是并列的不同代际，不是包含关系。deep_gemm 的 DeepEP 内核在编译时断言 `arch_major == 10`，即只支持 Blackwell，不支持 Hopper (H800)。

### 不满足条件汇总

| 不满足的条件 | 具体要求 | 当前环境 | 影响范围 |
|---|---|---|---|
| marlin 缺少 DeepEP fused func | `("deepep", "marlin")` 注册 | 无注册 | marlin 无法配合 DeepEP |
| triton 缺少 DeepEP pre-permute | `("deepep_normal", "triton")` 注册 | 无注册 | triton 无法配合 DeepEP |
| deep_gemm 需要 FP4 量化 | kPackedFP4 权重 | DSV4 是 FP8 模型 | deep_gemm 无法处理当前权重格式 |
| deep_gemm 需要 Blackwell GPU | arch_major == 10 | H800 (arch_major=9, Hopper) | deep_gemm 内核不兼容 Hopper 架构 |

## 结论

| 结论 | 说明 |
|---|---|
| **DeepEP 在 H800 + FP8 环境不可用** | 唯一兼容的 deep_gemm runner 需要 FP4 + Blackwell |
| **Marlin 不兼容 DeepEP** | 缺少 fused func 注册，属于 sglang 代码限制 |
| **Triton 不兼容 DeepEP** | 缺少 pre-permute 注册，属于 sglang 代码限制 |
| **DeepEP 需要 Blackwell GPU** | deep_gemm 要求 arch_major==10，H800 是 Hopper |

## 建议

如果未来要在 H800 上使用 DeepEP，最可行的路径是：
1. **sglang 代码层面**增加 `("deepep_normal", "triton")` 或 `("deepep_normal", "marlin")` 的 pre-permute/fused func 注册 — 这是让 DeepEP 在 H800 + FP8 环境下工作的最直接方式
2. **或者**在 Blackwell GPU (B200/B100) 环境中使用 FP4 量化模型 + deep_gemm + DeepEP 组合
