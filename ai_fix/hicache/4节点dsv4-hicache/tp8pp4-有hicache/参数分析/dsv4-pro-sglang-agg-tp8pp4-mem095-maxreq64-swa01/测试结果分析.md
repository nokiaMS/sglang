# DeepSeek-V4-Pro TP8PP4 HiCache 性能测试分析（mem=0.95, swa_full_tokens_ratio=0.1）

## 测试配置

- 模型: DeepSeek-V4-Pro
- 硬件: 4节点 × 8×H800 80GB (32 GPU)
- 框架: sglang v0.5.12.post1
- 并行: TP=8, PP=4
- HiCache: enabled (ratio=2.0, write_through, direct IO)
- mem-fraction-static: 0.95
- max-running-requests: 64
- swa-full-tokens-ratio: 0.1（默认值，未显式传参）
- 代码修复: hybrid_pool_assembler.py start_layer 偏移修复

## 关键发现

### 1. mem=0.95 相比 mem=0.90 整体性能提升

| 指标 | C10 R1 | C10 R3 | C30 R1 | C30 R3 | C60 R1 |
|------|--------|--------|--------|--------|--------|
| mem=0.90 Input (tok/s) | 5904 | 7658 | 11699 | 21991 | OOM |
| mem=0.95 Input (tok/s) | 6107 | 7726 | 11932 | 22351 | 28706 |
| 提升幅度 | +3.4% | +0.9% | +2.0% | +1.6% | 从 OOM→可用 |

mem=0.95 在 C10/C30 上有小幅提升（2-3%），最关键的改进是 C60 R1 从 OOM 变为可成功运行，Input throughput 达到 28706.50 tok/s。

### 2. C60 仅 R1 成功，R2 即 OOM 崩溃

C60 R1 成功运行，Input throughput 28706 tok/s，Output 113.72 tok/s。但 R2 启动后即触发 Prefill OOM，所有 8 个 TP scheduler 均崩溃。

原因分析：
- R1 成功是因为 C10/C30 的三轮压测已预热 HiCache，大量 KV 已从 GPU 迁移到 Host，为 prefill 腾出了空间
- R2 时，上一轮的 KV cache 状态使得 GPU 内存碎片化或 new request 的 prefill 内存需求叠加现有 cache 占用，超出可用空间
- mem=0.95 比 mem=0.90 多分配了 5% 显存给 KV cache，反而减少了 prefill 可用的临时内存空间，导致 C60 不稳定
- C60 R1 的 Mean TTFT 高达 13.6s（C30 R3 仅 3.1s），说明高并发下 prefill 已经非常吃力

### 3. HiCache 预热效应持续存在

与 mem=0.90 一致，三轮测试间性能逐轮大幅提升：

**C10:**
- R1→R3: Input throughput 6107→7726 (+26%), TTFT 2019→1096 (-46%)

**C30:**
- R1→R3: Input throughput 11932→22351 (+87%), TTFT 7057→3139 (-55%)

预热效应幅度与 mem=0.90 几乎相同，说明 HiCache 的 warmup 特性不受 mem-fraction-static 影响。

### 4. mem=0.95 vs mem=0.90 C60 稳定性对比

| 配置 | C60 R1 | C60 R2 | C60 R3 |
|------|--------|--------|--------|
| mem=0.90 swa=0.1 | OOM | OOM | OOM |
| mem=0.95 swa=0.1 | 28706 tok/s | OOM | OOM |

mem=0.95 使 C60 从完全不可用变为 R1 可用，但仍不够稳定。R2 崩溃的根本原因是 swa=0.1 下 GPU 可用内存不足以同时支撑 60 并发 prefill 和已有 KV cache。

### 5. 延迟分布分析

- **C60 R1 Mean TTFT 13.6s**: 远高于 C30 R3 的 3.1s，60 并发下 prefill 排队严重
- **C60 R1 Median TTFT 6.5s vs Mean 13.6s**: 长尾效应显著，部分请求等待极久
- **C30 长尾**: R1 P99 TTFT 34.4s（中位 2.5s），与 mem=0.90 表现一致

## 建议

1. **mem=0.95 不推荐用于生产**: 相比 mem=0.90 仅提升 2-3% 吞吐，且 C60 仍然不稳定（R2 OOM），不值得多分配 5% 显存
2. **swa=0.1 + C60 不可行**: 无论 mem=0.90 还是 0.95，swa=0.1 下 C60 都无法稳定运行。需要 swa≥0.2 或降低 max-running-requests
3. **推荐 swa=0.2 用于高并发场景**: swa=0.2 能稳定运行 C60，虽然低并发吞吐略低，但稳定性更重要
4. **HiCache 预热不可避免**: 无论 mem-fraction-static 如何配置，HiCache 预热效应都存在，部署后应有 warmup 阶段
