# 测试结果分析

## 测试结论

- 去掉 `--chunked-prefill-size 4096` 后，`TP=8, PP=4, DP=1` 服务可以正常启动，并完成 C10、C30、C60 三组压测。
- 9 轮压测全部成功，每轮 `Successful requests` 均为 100，测试过程中未观察到服务崩溃。
- 相比显式设置 `--chunked-prefill-size 4096` 的基线，本次不显式设置 chunked prefill 的吞吐整体下降，C10/C30 下降更明显，C60 接近但仍略低。
- 当前不建议去掉 `--chunked-prefill-size 4096`；基线配置中继续保留该参数更稳妥。

## 参数

```text
TP=8
PP=4
DP=1
HiCache=enabled
mem-fraction-static=0.95
max-running-requests=64
swa-full-tokens-ratio=0.2
chunked-prefill-size=未显式设置，使用 SGLang 默认值
disable-cuda-graph=true
disable-overlap-schedule=true
```

## 日志观察

- 服务端日志显示本次 HiCache host pool 规模略有变化，例如 node0 中 `host_pool_size=2016768`，对应 paged/state pool pages 为 `7878/1574`。
- 显式 `--chunked-prefill-size 4096` 基线中 node0 日志的 HiCache host pool 规模为 `host_pool_size=1966592`，pages 为 `7682/1536`。
- 去掉该参数后服务没有崩溃，但默认 chunked prefill 策略在当前 50000 input len、C10/C30/C60 负载下没有带来吞吐收益。

## 建议

- 保留 `--chunked-prefill-size 4096` 作为当前 TP8PP4 HiCache 场景的推荐配置。
- 不建议使用“不显式设置 chunked-prefill-size”作为主配置。
- 如果继续探索该参数，建议只在更大输入长度或不同 `max-running-requests` 下做局部对比；当前测试结果已经说明默认值不是本场景的最优选择。
