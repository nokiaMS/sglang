## 关键对比分析

### 1. C60 稳定性：hicache-ratio=3.0 反而恶化了 OOM 问题

| 配置 | C60 R1 | C60 R2 | C60 R3 |
|------|--------|--------|--------|
| hicache-ratio=2.0 | 12291 tok/s | 13151 tok/s | 12830 tok/s |
| hicache-ratio=3.0 | **OOM 崩溃** | **OOM 崩溃** | **OOM 崩溃** |

**这是最关键的发现。** hicache-ratio=3.0 在 C60 场景下完全不可用，而 hicache-ratio=2.0 可以稳定运行。

原因分析：
- `hicache-ratio` 定义的是 Host 内存池大小 = ratio × Device 内存池大小
- ratio=3.0 意味着 Host 内存池是 Device 的 3 倍（ratio=2.0 是 2 倍）
- 更大的 Host 内存池允许缓存更多冷 KV，但 **同时意味着 Host 内存占用增加 50%**
- 在 C60 高并发下，prefill 阶段需要大量临时 GPU 内存，而 Host 侧更大的内存池可能通过 pinned memory 等机制锁定了更多系统资源，间接加剧了 GPU 内存的分配压力
- 另一个可能的原因：更大的 Host pool 允许更多 KV 从 GPU offload 到 Host，GPU 上保留的 KV 更多（因为 offload 容量更大），导致后续 prefill 时 GPU 可用内存反而更少

### 2. C30 吞吐：hicache-ratio=3.0 大幅领先

| 指标 | C30 R1 | C30 R2 | C30 R3 |
|------|--------|--------|--------|
| hcr=2.0 Input (tok/s) | 10316 | 10815 | 10683 |
| hcr=3.0 Input (tok/s) | 16942 | 16782 | 16775 |
| **差异** | **+64.1%** | **+55.3%** | **+56.9%** |

| 指标 | C30 R1 | C30 R2 | C30 R3 |
|------|--------|--------|--------|
| hcr=2.0 Mean TPOT (ms) | 485.3 | 481.9 | 499.7 |
| hcr=3.0 Mean TPOT (ms) | 283.9 | 286.8 | 286.1 |
| **差异** | **-41.5%** | **-40.5%** | **-42.7%** |

hicache-ratio=3.0 在 C30 场景下表现极为出色：Input 吞吐提升 55-64%，TPOT 降低 40%以上。这是一个质变级别的改进。

原因分析：
- 更大的 Host 内存池可以容纳更多 offloaded KV，减少 KV 重计算
- C30 并发下 GPU 内存尚有余量，HiCache 的 offload 机制运行顺畅
- hicache-ratio=2.0 的 Host 池不够大，部分冷 KV 无法 offload 导致需要重新计算，TPOT 显著偏高

### 3. C10 吞吐：hicache-ratio=3.0 预热后反超

| 指标 | C10 R1 | C10 R2 | C10 R3 |
|------|--------|--------|--------|
| hcr=2.0 Input (tok/s) | 6095 | 6145 | 6107 |
| hcr=3.0 Input (tok/s) | 5878 | 6555 | 7669 |
| 差异 | -3.6% | +6.7% | **+25.6%** |

| 指标 | C10 R1 | C10 R2 | C10 R3 |
|------|--------|--------|--------|
| hcr=2.0 Mean TTFT (ms) | 2132 | 1929 | 1983 |
| hcr=3.0 Mean TTFT (ms) | 1941 | 1633 | 1000 |
| 差异 | -9.0% | -15.4% | **-49.6%** |

| 指标 | C10 R1 | C10 R2 | C10 R3 |
|------|--------|--------|--------|
| hcr=2.0 Mean TPOT (ms) | 295.7 | 289.6 | 291.7 |
| hcr=3.0 Mean TPOT (ms) | 302.6 | 270.4 | 234.1 |
| 差异 | +2.3% | -6.6% | **-19.7%** |

C10 R1 hicache-ratio=3.0 略逊于 2.0（冷启动），但 R2 开始反超，R3 大幅领先（+25.6%）。这说明 **hicache-ratio=3.0 有明显的 HiCache 预热效应**，而 hicache-ratio=2.0 则完全没有预热效应（三轮几乎无变化）。

### 4. HiCache 预热效应对比

**hicache-ratio=2.0 预热效应（swa=0.2 下）：**
- C10 R1→R3: Input +0.2%, TTFT -7.0%
- C30 R1→R3: Input +3.6%, TTFT +1.8%

**hicache-ratio=3.0 预热效应（swa=0.2 下）：**
- C10 R1→R3: Input **+30.5%**, TTFT **-48.5%**
- C30 R1→R3: Input -1.0%, TTFT -3.3%

关键发现：
- hicache-ratio=3.0 重新引入了显著的 HiCache 预热效应（在 swa=0.2 下本已消除）
- C10 从 R1 的 5878 飙升到 R3 的 7669 tok/s（+30.5%），与之前 swa=0.1 + hicache-ratio=2.0 的 C10 预热模式类似
- C30 的预热效应却很弱（R1 已经达到 16942，R3 仅 16775），说明 C30 并发下 Host 内存池在第一轮就已被充分填充

这暗示：**更大的 Host 内存池需要更多请求来"填满"**，在低并发（C10）下预热周期更长，但在中并发（C30）下首轮即可充分预热。

### 5. TPOT 全面对比

| 并发 | hcr=2.0 TPOT (ms) | hcr=3.0 TPOT (ms) | 差异 |
|------|--------------------|--------------------|------|
| C10 R3 | 291.7 | 234.1 | **-19.7%** |
| C30 R3 | 499.7 | 286.1 | **-42.7%** |
| C60 R3 | 607.4 | OOM | — |

hicache-ratio=3.0 在 C10/C30 下的 TPOT 大幅优于 2.0，尤其 C30 降低 42.7%。这说明更大的 Host 内存池有效减少了 KV 重计算，decode 阶段显著加速。

### 6. TTFT 全面对比

| 并发 | hcr=2.0 TTFT (ms) | hcr=3.0 TTFT (ms) | 差异 |
|------|--------------------|--------------------|------|
| C10 R3 | 1983 | 1000 | **-49.6%** |
| C30 R3 | 4744 | 2466 | **-48.0%** |
| C60 R3 | 22533 | OOM | — |

hicache-ratio=3.0 的 TTFT 全面减半，说明更大的 Host 缓存池使得 prefill 阶段可以更高效地处理请求（更少等待 GPU 内存释放）。

## 总结

| 维度 | hicache-ratio=2.0 | hicache-ratio=3.0 | 结论 |
|------|--------------------|--------------------|------|
| C10 吞吐（预热后） | 6107 | 7669 | hcr=3.0 胜 25.6% |
| C30 吞吐 | 10683 | 16775 | **hcr=3.0 胜 56.9%** |
| C60 稳定性 | 三轮全部成功 | **OOM 崩溃** | **hcr=2.0 胜** |
| C10 TPOT | 291.7 | 234.1 | hcr=3.0 胜 19.7% |
| C30 TPOT | 499.7 | 286.1 | hcr=3.0 胜 42.7% |
| C10 TTFT | 1983 | 1000 | hcr=3.0 胜 49.6% |
| C30 TTFT | 4744 | 2466 | hcr=3.0 胜 48.0% |
| 预热依赖 | 无 | C10 有（+30.5%） | hcr=2.0 胜 |
| 性能可预测性 | 好 | C10 波动较大 | hcr=2.0 胜 |

## 结论与建议

1. **hicache-ratio=3.0 在中低并发下性能优异，但 C60 不可用**：C30 吞吐提升 57%、TPOT 降低 43%、TTFT 减半，这是非常显著的改进。但 C60 完全 OOM，不能用于高并发生产环境

2. **hicache-ratio=3.0 引入了新的预热效应**：C10 R1→R3 吞吐提升 30.5%，这意味着冷启动性能较差（5878 tok/s vs hcr=2.0 的 6095），需要预热才能发挥优势

3. **C60 OOM 的根本原因需进一步分析**：更大的 Host 内存池反而导致 OOM，这可能与 pinned memory 锁定、GPU 内存碎片化或 HiCache 写回策略有关。建议检查 sglang 源码中 Host 内存池分配是否使用了 cudaHostRegister/pinned memory

4. **建议测试 hicache-ratio=2.5**：作为 2.0 和 3.0 之间的折中，可能在 C30 性能提升和 C60 稳定性间取得平衡

5. **场景化推荐**：
   - 确定并发 ≤ 30 的场景：**hicache-ratio=3.0**，性能优势巨大
   - 需要支持 60 并发的场景：**hicache-ratio=2.0**，牺牲部分吞吐换取 C60 稳定
   - 混合场景：考虑 hicache-ratio=2.5 或动态调整策略
