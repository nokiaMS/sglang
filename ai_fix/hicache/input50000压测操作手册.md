## 关键参数说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `--chunked-prefill-size` | 2048 | 解决挂起问题的关键参数，详见下方说明 |
| `--random-range-ratio` | 1.0 | 确保实际输入长度等于 `--random-input-len`，而非随机采样 |
| `--context-length` | 202752 | 模型上下文长度 |

### `--chunked-prefill-size` 参数详解

**基本作用：** 控制 prefill 阶段每次前向推理处理的最大 token 数。对长输入进行分块处理，避免单次 prefill 占用过多显存。

- 例如 `chunked_prefill_size=8192`（默认），输入 18000 token 需要分 3 轮 prefill（8192+8192+1616）
- 设为 `2048` 则需要 9 轮（2048×8+1616）

**对本问题的关键影响：**

`_swa_budget_for_req()`（`schedule_policy.py:553`）计算 SWA 预算时，使用 `min(extend_input_len, rem_chunk_tokens)` 作为估算值。其中 `rem_chunk_tokens` 是当前 chunk 的剩余 token 预算，上限为 `chunked_prefill_size`。由于 DeepSeek V4 的 `sliding_window=128`，SWA 实际只需要 128+256=384 个 token 的预算，但代码用 chunk 大小估算导致严重高估：

| `chunked_prefill-size` | SWA 预算计算 | SWA 预算值 | SWA pool 容量 | 结果 |
|------------------------|-------------|-----------|--------------|------|
| 8192（默认） | max(8192, 128) + 256 | 8448 | ~6425 | 挂起 |
| 2048 | max(2048, 128) + 256 | 2304 | ~6425 | 正常 |

**trade-off：** 更小的 chunk 意味着更多轮 prefill 迭代，会增加 TTFT。但从实测看影响不大（input=18000 时 TTFT 约 316ms，仍在合理范围）。

这只是规避方案，根本原因是 `_swa_budget_for_req` 用 `rem_chunk_tokens` 估算 SWA 需求，对 `sliding_window=128` 的 DeepSeek V4 严重高估。长期应修复该函数使 SWA 预算基于 `sliding_window_size` 而非 `extend_input_len` 计算。

## dsv-2节点-tp16pp1-启动后显存占比分析

### 单 GPU 显存分布

每张 GPU 总显存 79.65 GB（81559 MB），启动后显存分布如下：

| 用途 | 大小 | 占比 |
|------|------|------|
| 模型权重 | 68.48 GB | 86.0% |
| KV 缓存 | 4.72 GB | 5.9% |
| CUDA Graph | 0.53 GB | 0.7% |
| 空闲 | 5.92 GB | 7.4% |

> 数据来源：`get_server_info` API 的 `memory_usage` 字段 + `nvidia-smi`

### KV 缓存 Token 池分布

KV 缓存总 token 容量为 64256（`max_total_num_tokens`），DeepSeek V4 使用 DSV4 池配置器将其拆分为多个子池：

| 子池 | Token 容量 | 占比 | 说明 |
|------|-----------|------|------|
| Full pool | 64256 | 100% | 全注意力层 KV 缓存 |
| SWA pool | 6400 | 10% | 滑动窗口注意力层 KV 缓存（= full_pool × swa_full_tokens_ratio=0.1） |
| C4 pool | 16064 | 25% | 压缩注意力 4x 层（= full_pool / 4） |
| C128 pool | 502 | 0.8% | 压缩注意力 128x 层（= full_pool / 128） |

### 16 GPU 总计（TP=16）

| 用途 | 总大小 |
|------|--------|
| 总 GPU 显存 | 1274.36 GB |
| 模型权重 | 1095.68 GB |
| KV 缓存 | 75.50 GB |
| CUDA Graph | 8.48 GB |

### 显存分配流程

1. **加载模型权重**：占用 68.48 GB/GPU（86%），这是最大的显存开销
2. **计算 KV 缓存可用空间**：`可用显存 = (总显存 - 权重 - CUDA Graph) × mem_fraction_static(0.9)` ≈ (79.65 - 68.48 - 0.53) × 0.9 ≈ 9.58 GB
3. **DSV4 池配置器分配**：根据 `bytes_per_full_token`（含 full/swa/c4/c128 各层开销）计算 `full_token = available_bytes / bytes_per_full_token = 64256`，然后按比例分配各子池
4. **分配 CUDA Graph**：0.53 GB/GPU，用于 decode 阶段图捕获加速
